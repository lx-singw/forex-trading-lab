## Hash bytes, path and clock accounting

Each native065 hash consumes a read before any filesystem operation. It lstats
the file and **every parent**, stats the file before and after, rejects symlinks/
reparse flags, requires size1..128MiB, reads1MiB chunks, charges every byte,
and checks EOF/final clocks. It compares device/inode/size/mtime and exact bytes
read across that single acquisition. With N path nodes and K nonempty chunks,
there are N+2 path stats and N+5+2K clock checks per successful hash. Those finite
observations do not guarantee detection of every transient restored change.

The new count model calls the original `Meter065.consume` and `cleanup` numeric
predicates directly. It never instantiates that meter, renews its Oct7 date,
uses its900s window or claims a native clock sample. All retained083 historical
Oct8 timing checks and2s/10s/30–31s/250ms/60s/120s windows remain unchanged.
Native cost, actual clock behavior and uninterruptible IO remain unverified.
The reader clock counter has its own original610,000 count cap; it is not
silently merged with or discounted against the independent4096 raw/bridge caps.

An arithmetic full-target projection counts every individual role and source
path, including duplicate shell/script acquisitions and identity image hashes.
It uses public canonical Linux source sizes/depths and explicitly synthetic
one-byte private Windows image profiles. Linux ancestry is not an actual Windows
deployment mapping; private image sizes are not measured. This illustrative
projection also exceeds the16,384 path-stat cap. Its byte/clock/process totals
are conditional, not proof that those other native budgets would fit. SDK,
provider, loaded-module discovery and runner child ownership add separate work.
No actual image path, process/account identifier or credential is exported.

Three injected filesystem tests execute the **actual** native065 hash method
unbound, without its constructor/DLLs, over memory streams and synthetic stat
objects. They confirm the chunk/byte/complete-path/EOF clock counts agree with
the model. They do not validate Windows behavior, loaded modules or IO safety.
Digest/process/SDK values in the coupled episode remain frozen fixture values.

## Representation feasibility

An unchanged archive hash cannot detect a change to a separately mutable helper
or canonical source file. A manifest describes expected bytes, not the current
bytes of those paths. Batch hashing still needs each read; labeling a batch as
one read conceals acquisition cost. Retained handles or cached digests across
guards cannot prove current content. A single-pass or reduced-source proof
would weaken the individually required before/after provenance facts.

No representation meeting those facts fits768 reads. Accordingly there is no
new reader, source consolidation, cache, archive substitution, larger cap or
native stage. The admission entry always rejects. Frozen positive089 injected
core episodes remain useful software evidence, with zero native authority.

The earlier raw-wire fake source/artifact/policy pins and model-build pins were
not one verified executable provenance chain. The089 model only joins peer/
clock/boot facts across those components. This additional open obligation
reinforces the limit on interpreting its positive count models; no old evidence
is changed and no native source/build coherence is claimed.
